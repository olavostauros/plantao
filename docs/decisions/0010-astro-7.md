# 0010 — Astro 7

**Data:** 2026-10-13

## Contexto

A auditoria de segurança de 2026-10-13 (P-002) apontou avisos no Astro 5.18.2 e no sharp e no
esbuild que vêm com ele; a correção só existe na linha 7 (≥ 7.3.8). Nenhum caminho do site
alcançava o código vulnerável (saída `static`, sem otimização de imagem), mas o risco aparece no
dia em que um desses recursos for usado. No mesmo pacote, P-003: markdown-it e KaTeX.

## Decisão

- `astro` 7.3.8 e `@astrojs/preact` 6.0.6 (a linha compatível; Vite 8, sem esbuild na árvore).
  `@astrojs/check` continua 0.9.10 e `preact` continua 10.29.8.
- `markdown-it` 14.3.2 (correção dentro do major 14, como pede o P-003; a 15 fica para quando
  houver motivo) e `katex` 0.19.0.
- Nenhuma API do site mudou. Nos testes, `getContainerRenderer` passa a vir de
  `@astrojs/preact/container-renderer` (o import pela raiz ficou obsoleto).

## Consequências

- `npm audit` sem nenhum aviso (antes: 5 pacotes).
- O compilador do Astro 7 tira o espaço em branco entre tags no HTML gerado. O texto visível das
  67 páginas é o mesmo (comparado com o build do Astro 5, normalizando espaço); a única diferença
  é entre os links "← Questão N" e "Questão N →", que ficam num `flex` com `gap` e não mudam na
  tela. Texto que precisa de espaço entre dois elementos em linha deve tê-lo dentro de um deles
  ou como `{' '}`.
- Pesos (gzip) quase iguais: página de questão ≈ 8,9 KB de JS em `_astro/` (antes ≈ 8,7 KB),
  busca 18,5 KB no `SearchApp` (antes 18,6 KB), CSS 3,8 KB.
